## 练习 1 · 跑马灯（PB0~PB7）

### 1.1 关键寄存器值（先手算）

PB0~PB7 都在 **`CRL`**，每引脚 4 位：

| 引脚 | 位段 | 配置值 | 含义 |
|---|---|---|---|
| PB0 | `CRL[3:0]` | `0x2` | MODE=10(2MHz) CNF=00(通用推挽) |
| PB1 | `CRL[7:4]` | `0x2` | 同上 |
| … | … | `0x2` | 同上 |
| PB7 | `CRL[31:28]` | `0x2` | 同上 |

8 个引脚全是 `0x2` → **`GPIOB->CRL = 0x22222222`**（复位值 `0x44444444`，直接整体覆盖即可）

### 1.2 HAL 版

```c
#include "stm32f1xx_hal.h"

#define MARQUEE_PORT            GPIOB
#define MARQUEE_PINS            0x00FFU          /* PB0~PB7，低电平点亮 */
#define MARQUEE_PIN_MASK        (GPIO_PIN_0 | GPIO_PIN_1 | GPIO_PIN_2 | GPIO_PIN_3 | \
                                 GPIO_PIN_4 | GPIO_PIN_5 | GPIO_PIN_6 | GPIO_PIN_7)

static void Marquee_Init_HAL(void)
{
    GPIO_InitTypeDef gpio = {0};

    __HAL_RCC_GPIOB_CLK_ENABLE();

    gpio.Pin   = MARQUEE_PIN_MASK;
    gpio.Mode  = GPIO_MODE_OUTPUT_PP;
    gpio.Pull  = GPIO_NOPULL;
    gpio.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(MARQUEE_PORT, &gpio);

    HAL_GPIO_WritePin(MARQUEE_PORT, MARQUEE_PIN_MASK, GPIO_PIN_SET);  /* 全灭 */
}

static void Marquee_Run_HAL(uint32_t stepMs)
{
    for (uint8_t i = 0; i < 8U; i++)
    {
        uint16_t pin = (uint16_t)(1U << i);

        HAL_GPIO_WritePin(MARQUEE_PORT, pin, GPIO_PIN_RESET);   /* 亮 */
        HAL_Delay(stepMs);
        HAL_GPIO_WritePin(MARQUEE_PORT, pin, GPIO_PIN_SET);     /* 灭 */
    }
}
```

### 1.3 寄存器版（对照着看差别）

```c
static void Marquee_Init_REG(void)
{
    RCC->APB2ENR |= RCC_APB2ENR_IOPBEN;     /* 开 GPIOB 时钟 */
    GPIOB->CRL    = 0x22222222U;            /* PB0~PB7 全部推挽输出 2MHz */
    GPIOB->BSRR   = 0x000000FFU;            /* 低 16 位写 1 → 全部置高 → 全灭 */
}

static void Marquee_Run_REG(uint32_t stepMs)
{
    for (uint8_t i = 0; i < 8U; i++)
    {
        GPIOB->BSRR = (uint32_t)(1U << i) << 16U;   /* 高 16 位写 1 → 置低 → 亮 */
        HAL_Delay(stepMs);
        GPIOB->BSRR = (uint32_t)(1U << i);          /* 低 16 位写 1 → 置高 → 灭 */
    }
}
```

> **`BSRR` 的两种用法要刻进肌肉记忆**：
> ```c
> GPIOB->BSRR = pin;                 /* 置高（Set） */
> GPIOB->BSRR = (uint32_t)pin << 16; /* 置低（Reset） */
> ```

### 1.4 板上只有 2 个 LED 怎么办

`PB0~PB7` 没有 8 个 LED 可接，有两种替代验证：

| 方法 | 做法 |
|---|---|
| **A · 用调试器看 ODR** | 不接 LED，单步跑 `Marquee_Run_*`，在 XPERIPHERALS 看 `GPIOB → ODR` 的 bit0~bit7 依次变化 |
| **B · 用现有 2 个 LED** | 把 `LED_1`(PA8)、`LED_2`(PB15) 交替点亮，就是"两灯跑马" |

> **方法 A 的价值**：它证明你写的位运算**真的作用到了硬件上**，比灯更直接。

## 练习 2 · 呼吸灯（软件 PWM）

### 2.1 原理

**PWM = 用固定频率开关，靠"亮的时间占比"（占空比）调平均亮度。**

```
占空比 = 0%          占空比 = 25%         占空比 = 50%
亮   ┌───────┐        亮 ┌─┐ ┌─┐ ┌─┐        亮 ┌──┐ ┌──┐
     │       │           │ │ │ │ │ │           │  │ │  │
灭   ┘       └───      灭 ┘ └─┘ └─┘ └─      灭 ┘  └─┘  └─

人眼看到：全灭        →     很暗        →      半亮
```

**关键条件**：开关频率必须 **> 100Hz**（人眼闪烁融合频率，约 60~90Hz）。
频率够高 → 看不到闪 → 只看到"平均亮度"。**这正是你上次写错 `Key_Scan` 时看到"LED 半亮"的同一个原理。**

### 2.2 实现

```c
/* 软件 PWM 呼吸灯
 * P     : 一个 PWM 周期的"份数"（决定频率：份数越多频率越低）
 * RANGE : 亮度分多少级（决定渐变的平滑度）
 * 停留  : 每一级亮度停留多久（决定呼吸快慢）
 */
static void Led_Breath(void)
{
    const uint32_t P      = 1000U;    /* 一个周期 1000 份 */
    const uint32_t RANGE  = 200U;     /* 亮度 200 级 */
    const uint32_t HOLD_MS = 10U;     /* 每级停留 10ms */

    for (;;)                          /* 无限呼吸 */
    {
        /* 渐亮：占空比 0% → 100% */
        for (uint32_t d = 0; d <= RANGE; d++)
        {
            uint32_t on = (d * P) / RANGE;
            uint32_t t0 = HAL_GetTick();

            while (HAL_GetTick() - t0 < HOLD_MS)
            {
                Led_On(LED_1);
                for (volatile uint32_t i = 0; i < on; i++) { }
                Led_Off(LED_1);
                for (volatile uint32_t i = 0; i < (P - on); i++) { }
            }
        }

        /* 渐暗：占空比 100% → 0% */
        for (uint32_t d = RANGE; d > 0U; d--)
        {
            uint32_t on = (d * P) / RANGE;
            uint32_t t0 = HAL_GetTick();

            while (HAL_GetTick() - t0 < HOLD_MS)
            {
                Led_On(LED_1);
                for (volatile uint32_t i = 0; i < on; i++) { }
                Led_Off(LED_1);
                for (volatile uint32_t i = 0; i < (P - on); i++) { }
            }
        }
    }
}
```

### 2.3 调参指南（**这是这个练习真正的重点**）

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 看到 LED 在**闪**，不是渐变 | PWM 频率太低（周期太长） | **减小 `P`** |
| 亮度变化**一跳一跳**的 | `RANGE` 太小 | **增大 `RANGE`** |
| 呼吸太快 | 每级停留太短 | **增大 `HOLD_MS`** |
| 最亮时不够亮 / 最暗时不够暗 | `on` 没到 0 或 P | 检查循环边界（`<=` / `>`） |

> **必须要自己调一遍**。这四行参数和三个现象之间的对应关系，就是"PWM 三要素"（频率、占空比、分辨率）：
> - **频率** 由 `P`（+ CPU 速度）决定 —— 太低调不动人眼的"视觉暂留"
> - **占空比** 由 `on/P` 决定 —— 决定亮度
> - **分辨率** 由 `RANGE` 决定 —— 决定渐变是否平滑

> **这是第 05 章"硬件 PWM"的预习**：硬件 PWM 用定时器自动产生波形，CPU 完全不占用，而这里 CPU 被 100% 占满。

## 练习 4 · `HAL_GPIO_TogglePin` vs `ODR ^=` 对比

### 4.1 三种写引脚方式的**源码对照**（F1 HAL）

**`HAL_GPIO_WritePin()`** —— 定点写，**直接走 BSRR，无读操作**

```465:479:STM32_Hal/Src/stm32f1xx_hal_gpio.c
void HAL_GPIO_WritePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin, GPIO_PinState PinState)
{
  if (PinState != GPIO_PIN_RESET)
  {
    GPIOx->BSRR = GPIO_Pin;                       /* 置高 */
  }
  else
  {
    GPIOx->BSRR = (uint32_t)GPIO_Pin << 16u;      /* 置低 */
  }
}
```

**`HAL_GPIO_TogglePin()`** —— **先读 `ODR`，再决定写 `BSRR` 还是 `BRR`**

```487:500:STM32_Hal/Src/stm32f1xx_hal_gpio.c
void HAL_GPIO_TogglePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin)
{
  if ((GPIOx->ODR & GPIO_Pin) != 0x00u)
  {
    GPIOx->BRR = (uint32_t)GPIO_Pin;      /* 当前是 1 → 清 0 */
  }
  else
  {
    GPIOx->BSRR = (uint32_t)GPIO_Pin;     /* 当前是 0 → 置 1 */
  }
}
```

**`GPIOA->ODR ^= GPIO_PIN_8;`** —— 编译器展开是**读-改-写三步**

```c
tmp = GPIOA->ODR;      /* ① 读整个 ODR（16 位） */
tmp ^= GPIO_PIN_8;     /* ② 软件异或 */
GPIOA->ODR = tmp;      /* ③ 整个字写回 */
```

### 4.2 结论

| 方式 | 读？ | 写？ | 原子性 | 风险 |
|---|---|---|---|---|
| `HAL_GPIO_WritePin()` | ❌ | `BSRR` 单次写 | **完全原子** | 无 |
| `HAL_GPIO_TogglePin()` | ✅ 读 `ODR` | `BRR`/`BSRR` 单次写 | **写原子，但读有窗口** | 读→写之间被中断打断，可能翻转错误 |
| `ODR ^=` | ✅ 读 `ODR` | **整个 `ODR` 写回** | **不安全** | 读→写之间被中断打断，**其他引脚的改动会被覆盖丢失** |

**三个要点**：

1. **`ODR ^=` 最危险的地方不是"翻转错"，而是"整个字写回"** —— 如果中断里改了**同一个端口的其他引脚**，你那一次异或会把中断的改动**一起覆盖掉**。
2. `HAL_GPIO_TogglePin()` 比 `ODR ^=` 好，因为它把"写"用 `BSRR`/`BRR` 做成了**只影响目标位**，不会覆盖别的引脚；但"读 `ODR`"这一步仍然有窗口。
3. **真正无窗口的做法**：一个引脚只由"一个上下文"写（要么只在主循环、要么只在中断），或者干脆**用 `WritePin` 显式指定电平**，而不是"翻转"。

> **实践建议**：
> - 需要**确定电平** → 用 `HAL_GPIO_WritePin()`（或 `BSRR` 直写）—— **永远安全**
> - 需要**翻转** → 用 `HAL_GPIO_TogglePin()`（或 `BSRR` + 读 `ODR` 自己算）
> - **`ODR ^=` 只适合"单线程 + 该端口没有别的使用者"** 的简单场景

### 4.3 波形对比（逻辑分析仪 / 示波器）

两种方式**波形完全一样**（都是方波），所以示波器看不出区别——**这个练习的价值在"读源码"，不在"看波形"**。

> **注意**：你在 `README.md` 里写的"用逻辑分析仪对比波形"这个预期是**不对的**——差异在**并发场景下**才会暴露，不在波形本身。
> **想看到差异，必须造并发**：在 `EXTI` 中断里改同端口的另一个引脚，主循环里用 `ODR ^=` 翻转本引脚，多次触发后观察"另一个引脚的电平被莫名改掉"。这个实验放到**第 03 章学完 EXTI 之后**做最有说服力。

## 练习 5 · 查手册：`GPIOx_BSRR` / `GPIOx_BRR` 位定义

### `GPIOx_BSRR`（Port bit set/reset register，偏移 `0x10`）

| 位 | 名称 | 含义 |
|---|---|---|
| `[15:0]` | `BSy` (y=0..15) | 写 **1** → `ODRy` **置 1**（输出高）；写 **0** → **无影响** |
| `[31:16]` | `BRy` (y=0..15) | 写 **1** → `ODRy` **清 0**（输出低）；写 **0** → **无影响** |

**三个必须记住的性质**：

1. **写 0 不产生任何影响** → 所以不需要"先读再改"，**天然原子**
2. **只影响你写 1 的那些位** → 同一个端口上别的引脚不受干扰
3. **`BSy` 和 `BRy` 同时为 1 时，`BSy` 优先**（即置位优先）

### `GPIOx_BRR`（Port bit reset register，偏移 `0x14`）

| 位 | 名称 | 含义 |
|---|---|---|
| `[15:0]` | `BRy` | 写 1 → `ODRy` 清 0 |
| `[31:16]` | 保留 | — |

**`BRR` 就是 `BSRR` 的高 16 位单独抽出来的版本**，只能"置低"。
所以 **F1 里 `BRR` 是历史遗留**——有 `BSRR` 就够了（`BSRR` 的 `[31:16]` 等价于 `BRR`），**日常只用 `BSRR`**。

### 三个常用写法（背下来）

```c
GPIOA->BSRR = GPIO_PIN_8;                            /* PA8 置高 */
GPIOA->BSRR = (uint32_t)GPIO_PIN_8 << 16;            /* PA8 置低（等价 GPIOA->BRR = GPIO_PIN_8） */
GPIOA->BSRR = GPIO_PIN_8 | ((uint32_t)GPIO_PIN_9 << 16);  /* 一次操作：PA8 置高 + PA9 置低 */
```

> 最后一行最能体现 `BSRR` 的价值：**一条指令，同时设置多个引脚到不同电平，且绝对不会影响其他位。**

## 附加 · 开漏输出验证实验（对应学习目标 #5）

### 原理：开漏为什么必须外部上拉

```
        推挽输出                          开漏输出
     ┌─────┐                          ┌─────┐
VDD ─┤ P-MOS ├─┐                VDD ─┤  ×   │  ← 没有 P-MOS！
     └─────┘  │                      └─────┘
          引脚 ●                         引脚 ●
     ┌─────┐  │                      ┌─────┐  │
GND ─┤ N-MOS ├─┘                GND ─┤ N-MOS ├─┘
     └─────┘                          └─────┘

输出 1 → P-MOS 导通 → 拉到 VDD ✅    输出 1 → 两个管子都关 → 引脚【悬空】❌
输出 0 → N-MOS 导通 → 拉到 GND      输出 0 → N-MOS 导通 → 拉到 GND ✅
```

**一句话**：**开漏输出只能"拉低"，不能"拉高"。** 输出 1 时它做的是"**松开手**"（高阻），而不是"把电平顶到 3.3V"。所以想让高电平出现，**必须由外部上拉电阻把线拉上去**。

### 验证实验（安全版，不需要额外器件）

用一块**空引脚**（比如 `PA11`，板上没接任何东西）：

```c
/* PA11 配成开漏输出 */
RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;
GPIOA->CRH &= ~(0xFU << 12);      /* PA11 → CRH bits[15:12] */
GPIOA->CRH |=  (0x7U << 12);      /* MODE=11(50MHz) CNF=01(通用开漏) */
```

然后按顺序做：

| 步 | 操作 | 读 `GPIOA->IDR` 的 bit11 | 说明 |
|---|---|---|---|
| 1 | 输出 0：`GPIOA->BSRR = GPIO_PIN_11 << 16;` | **`0`** | 引脚被 N-MOS 拉到 GND ✅ |
| 2 | 输出 1：`GPIOA->BSRR = GPIO_PIN_11;` | **不稳定 / 为 0** | 引脚**悬空**，读到的是环境噪声 ⚠️ |
| 3 | 在 PA11 与 3.3V 之间接一个 **10kΩ 电阻** | 输出 1 时 **`1`**，输出 0 时 `0` | 上拉电阻补上了缺失的 P-MOS ✅ |

> **第 2 步的"不稳定"就是开漏的本质**：它不是高电平，是"没有电平"。
> **如果你用万用表测，会看到电压在 0~3.3V 之间飘**——这就是最直观的证据。

### 为什么 I2C 必须用开漏（理解这条才算真懂）

```
如果 I2C 用推挽输出：

  主机(推挽)           从机(推挽)
  输出 1 ──┐           输出 0 ──┐
   P-MOS 导通          N-MOS 导通
           ↓                    ↓
      VDD ── 3.3V ──────── GND ── 0V
              └──── 直接短路！ ────┘
                 电流 = 3.3V / (极小阻抗)
                 → 引脚烧毁 🔥

用开漏输出：

  主机 ─ 输出 1 = 高阻（松手）
  从机 ─ 输出 0 = 拉低
        ↓
     总线被拉低 = 0   ← 这就是"线与"：任何一方拉低，总线就是低
     完全没有短路电流 ✅
```

**三条结论**：

1. **多设备共享一条线，必须用开漏** —— 否则一高一低就是短路
2. **开漏 + 外部上拉 = "线与"逻辑** —— 谁都能拉低，没人能强行拉高，**天然避免冲突**
3. **上拉电阻还顺便实现了电平转换** —— 3.3V 的 MCU 可以把线拉到 5V，与 5V 器件通信

> **第 13 章学 I2C 时，你会亲手量 SDA/SCL 上的上拉电阻，也会亲眼看到"ACK 是靠从机拉低产生的"** —— 那时候再回来看这一节，就全通了。
