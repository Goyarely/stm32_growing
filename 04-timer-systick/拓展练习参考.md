## 练习 1 · 精准周期任务（对比累计误差）

### 目标

同样"每 1 秒翻转一次 LED1"，做两个版本，各跑 1 分钟，看谁准。

### 版本 A · `HAL_Delay` 版

```c
/* App/main.c */
uint32_t t0 = HAL_GetTick();
for (uint8_t i = 0; i < 60U; i++)       /* 60 次 × 1s = 60s */
{
    HAL_Delay(1000);
    Led_Toggle(LED_1);
}
uint32_t t1 = HAL_GetTick();
volatile uint32_t g_elapsedA = t1 - t0;  /* 用变量面板读 */
```

### 版本 B · 定时器版

```c
/* Driver/tim.c 的回调里 */
static uint32_t s_cnt = 0;

if (htim->Instance == TIM2)
{
    if (++s_cnt >= 1000U)      /* 1000 × 1ms = 1s */
    {
        s_cnt = 0;
        Led_Toggle(LED_1);
    }
}
```

```c
/* main.c 里同样测 60 次翻转的时间 */
uint32_t t0 = HAL_GetTick();
/* 等 g_toggleCnt 增加 60（或用 HAL_Delay 粗等 60s 后读 t1） */
uint32_t t1 = HAL_GetTick();
volatile uint32_t g_elapsedB = t1 - t0;
```

### ⭐ 标准答案（含一个"必然"的发现）

| 版本 | `g_elapsed` 期望值 | 真正会发生什么 |
|---|---|---|
| A · `HAL_Delay` | 60000 | **≈ 60060**（每分钟**多 60ms**） |
| B · TIM2 | 60000 | **≈ 60000 ± 几 ms** |

### 为什么 A 必然多 60ms —— 去读源码

```360:373:04-timer-systick/STM32_Hal/Src/stm32f1xx_hal.c
  uint32_t tickstart = HAL_GetTick();
  uint32_t wait = Delay;

  /* Add a freq to guarantee minimum wait */
  if (wait < HAL_MAX_DELAY)
  {
    wait += (uint32_t)(uwTickFreq);
  }

  while ((HAL_GetTick() - tickstart) < wait)
  {
  }
```

**第 368 行：`wait += uwTickFreq`（= 1）**。

```
HAL_Delay(1000)  →  wait = 1001  →  实际等 1001ms
60 次            →  60 × 1001ms = 60060ms
                                   ↑
                              多 60ms（+0.1%）
```

> **为什么 HAL 要故意多等 1ms？** 因为 `HAL_GetTick()` 是 1ms 粒度的，不加这 1ms 的话，`HAL_Delay(1)` 可能**立刻返回**（等 0ms）。
> **代价就是每次调用都至少慢 1ms。**

### 结论（写进笔记）

```
- HAL_Delay 有 +1 tick 的固有开销 → 周期任务会累积漂移（+0.1%）
- 定时器中断由硬件计数驱动 → 无累积漂移，误差只来自晶振本身（ppm 级）
- 所以【周期任务】必须用定时器，【偶尔等一下】才用 HAL_Delay
```

## 练习 2 · 软件 PWM（100 级）⭐ 第 05 章引子

### 代码

```c
/* Driver/tim.c */
static volatile uint8_t s_pwmDuty = 50U;    /* 占空比 0~100，先给 50% */
static uint8_t          s_pwmCnt  = 0U;

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        /* ---- 软件 PWM：100 级 ---- */
        if (++s_pwmCnt >= 100U)
        {
            s_pwmCnt = 0U;
        }

        /* LED1 = PA8，【低电平点亮】
         * cnt < duty → 输出低 → 亮；其余 → 输出高 → 灭 */
        HAL_GPIO_WritePin(GPIOA, GPIO_PIN_8,
                          (s_pwmCnt < s_pwmDuty) ? GPIO_PIN_RESET : GPIO_PIN_SET);
    }
}

void Tim_SetDuty(uint8_t duty)      /* 给按键用 */
{
    s_pwmDuty = (duty > 100U) ? 100U : duty;
}

uint8_t Tim_GetDuty(void)
{
    return s_pwmDuty;
}
```

### 用按键调亮度（接上你已有的 `Key_Task`）

```c
/* App/main.c 的 while(1) 里 */
if (Key_HasEvent(KEY1))                 /* 按 SW2 → 变亮 */
{
    HAL_Delay(20);
    if (Key_IsPressed(KEY1))
    {
        Tim_SetDuty(Tim_GetDuty() + 10U);
    }
}
if (Key_HasEvent(KEY2))                 /* 按 SW3 → 变暗 */
{
    HAL_Delay(20);
    if (Key_IsPressed(KEY2))
    {
        Tim_SetDuty(Tim_GetDuty() - 10U);
    }
}
```

### 现象与调参指南（**这段最重要**）

**PWM 频率** = `1 / (100 级 × 1ms)` = **10Hz**

| 你看到的 | 原因 |
|---|---|
| LED **在闪**，不是"变暗" | 10Hz 太慢，人眼能分辨 |
| 占空比 50% 时，亮/灭各 50ms | 周期 100ms |

| 想改什么 | 改哪里 | 副作用 |
|---|---|---|
| **频率更高**（让它像"变暗"） | ARR 从 9 改成更小（如 0）→ ISR 变快 | **CPU 占用暴涨**（中断更频繁） |
| **分辨率更细**（更多亮度级） | 100 → 200 级 | PWM 频率**减半** |
| **CPU 占用更低** | 级数减少（如 20 级） | 亮度变成**明显台阶** |

### ⭐ 这道题真正要你看到的：**软件 PWM 的三重困境**

```
   频率  ×  分辨率  =  1 / ISR周期      ← 定了 ISR 周期，两者此消彼长
            ↑
   CPU 占用 ∝ ISR 频率 → 频率想高，CPU 就被吃掉
            ↓
   而且：ISR 里一秒钟跑上万次，只为翻转一个引脚 —— 极度浪费
```

**这正是第 05 章"硬件 PWM"要解决的问题**：

| | 软件 PWM（现在） | 硬件 PWM（第 05 章） |
|---|---|---|
| CPU 占用 | 高（ISR 每秒上万次） | **0**（硬件自动翻转，不用中断） |
| 最高频率 | 低（受 ISR 速度限制） | **高**（可达 MHz） |
| 分辨率 | 10~200 级 | **最高 65536 级** |
| 改占空比 | 改变量（要判边界） | **写 `TIMx->CCRy` 一个寄存器** |

> **先亲手做出"10Hz、会闪、CPU 还很忙"的软件 PWM，第 05 章你才会真心觉得硬件 PWM 好用。**

## 练习 3 · 电子时钟雏形

### 代码

```c
/* 定时器：纯累加，不做别的（干净） */
volatile uint32_t g_ms = 0;

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        g_ms++;                     /* 1ms 累加 */
    }
}
```

```c
/* App/main.c：1 秒粒度地打印 */
static uint32_t s_lastSec = 0;

void Clock_Task(void)
{
    uint32_t totalSec = g_ms / 1000U;

    if (totalSec == s_lastSec)
    {
        return;                     /* 还是同一秒，什么也不做 */
    }
    s_lastSec = totalSec;

    uint32_t h = totalSec / 3600U;
    uint32_t m = (totalSec % 3600U) / 60U;
    uint32_t s = totalSec % 60U;

    /* ① 变量面板版（现在就能用） */
    volatile uint32_t g_h = h, g_m = m, g_s = s;

    /* ② 串口版（第 07 章做完 printf 重定向后启用）
     * printf("Uptime %02lu:%02lu:%02lu\r\n",
     *        (unsigned long)h, (unsigned long)m, (unsigned long)s);
     */
}
```

```c
while (1)
{
    Clock_Task();
    Key_Task(KEY1, LED_1);
    Key_Task(KEY2, LED_2);
}
```

### 标准答案说明

| 项 | 说明 |
|---|---|
| **为什么用 1 秒粒度判断** | 主循环一圈才几 μs，不加这个判断会**每秒打印几十万次** |
| `g_ms / 1000U` | 整数除法，天然取整 |
| `%` 运算 | 求余，拆出 时/分/秒 |
| **`g_ms` 溢出** | `uint32_t` 约 **49.7 天**后回绕。回绕后 `g_ms/1000` 会突然跳回 0 —— 秒表会"归零"。**做产品要处理，学习阶段知道即可** |
| 串口打印 | **依赖第 07 章的 `printf` 重定向**，本章先用「变量面板」看 `g_h/g_m/g_s` |
| 与 RTC 的区别 | 这是**秒表（从上电开始累计）**；第 10 章的 **RTC** 才有年月日、掉电走时 |

### 加强版（可选，5 分钟）

用 LED 表示秒，不用示波器也能"看见"：

```c
/* 回调里同时做个"秒闪" */
static uint32_t s_secCnt = 0;

if (++s_secCnt >= 1000U)
{
    s_secCnt = 0;
    Led_Toggle(LED_2);          /* LED2 每 1 秒翻转一次 → 1 秒一个完整亮灭周期？不，是每 2 秒一个周期 */
}
```

> `Led_Toggle` 每 1 秒翻一次 → **2 秒一个完整亮灭周期**。
> 要和手机秒表对齐，就盯着"亮→灭"数 1 秒。

## 练习 4 · 定时器级联（TIM2 触发 TIM3，实现超长定时）

### 核心思路

```
TIM2 溢出 ──(内部 TRGO/ITR 连线，不经过任何引脚)──► TIM3 的计数时钟
                                                        │
                                               TIM3 每收到 1 个脉冲 CNT+1
```

**定时上限 = TIM2 周期 × TIM3 周期**（相乘！这就是突破 16 位的办法）

**ITR 连线（查参考手册）**：TIM3 的 `ITR1` = TIM2。

### 目标：**1 小时**

```
TIM2：PSC = 7199, ARR = 9999  →  (7200 × 10000) / 72MHz = 1s
TIM3：ARR = 3599              →  3600 × 1s = 3600s = 1 小时 ✅
```

（TIM2 的 ARR = 9999 ≤ 65535 ✓，TIM3 的 ARR = 3599 ≤ 65535 ✓）

### 代码

```c
void Tim_Cascade_Init(void)
{
    /* ---------- TIM2：主定时器，1s 溢出，并把更新事件输出到 TRGO ---------- */
    RCC->APB1ENR |= RCC_APB1ENR_TIM2EN;

    TIM2->PSC = 7199;
    TIM2->ARR = 9999;                       /* 1s */
    TIM2->EGR = TIM_EGR_UG;
    TIM2->SR  = 0;

    /* ★ MMS = 010 → 更新事件作为 TRGO 输出（关键！没这句 TIM3 收不到脉冲） */
    TIM2->CR2 &= ~TIM_CR2_MMS;
    TIM2->CR2 |=  TIM_CR2_MMS_1;            /* MMS[2:0] = 010 */

    TIM2->CR1 |= TIM_CR1_CEN;

    /* ---------- TIM3：从定时器，由 TIM2 的更新事件驱动 ---------- */
    RCC->APB1ENR |= RCC_APB1ENR_TIM3EN;

    TIM3->PSC = 0;                          /* 不预分频：1 个输入脉冲 = CNT+1 */
    TIM3->ARR = 3599;                       /* 3600 个脉冲 = 3600s = 1 小时 */
    TIM3->EGR = TIM_EGR_UG;
    TIM3->SR  = 0;

    /* ★ 时钟源选 ITR1（= TIM2） */
    TIM3->SMCR &= ~TIM_SMCR_TS;
    TIM3->SMCR |=  TIM_SMCR_TS_0;           /* TS[2:0] = 001 → ITR1 = TIM2 */

    /* ★ 从模式选"外部时钟模式 1"：用外部脉冲驱动计数 */
    TIM3->SMCR |= (TIM_SMCR_SMS_2 | TIM_SMCR_SMS_1 | TIM_SMCR_SMS_0);   /* SMS = 111 */

    /* 使能 TIM3 更新中断，回调里翻转 LED */
    TIM3->DIER |= TIM_DIER_UIE;
    HAL_NVIC_SetPriority(TIM3_IRQn, 2, 0);
    HAL_NVIC_EnableIRQ(TIM3_IRQn);

    TIM3->CR1 |= TIM_CR1_CEN;
}
```

```c
/* stm32f1xx_it.c */
void TIM3_IRQHandler(void)
{
    if ((TIM3->SR & TIM_SR_UIF) != 0U)
    {
        TIM3->SR = (uint32_t)~TIM_SR_UIF;
        Led_Toggle(LED_1);                  /* 每 1 小时翻一次 */
    }
}
```

### 标准答案说明

| 项 | 说明 |
|---|---|
| **必须设 `MMS`** | 不设 `TIM2->CR2.MMS`，TIM2 的 TRGO 不发更新事件 → TIM3 永远不计数（**最常见的坑**） |
| `TS = 001` | 对 **TIM3** 来说，`ITR1` 才是 TIM2（`ITR0` 是 TIM1） |
| `SMS = 111` | "外部时钟模式 1" = 用外部脉冲驱动 CNT |
| **上限** | TIM2 最长约 59.6s（PSC=ARR=65535），再乘 TIM3 的 65536 → 约 **45 天** |
| 实用价值 | 真正需要"小时/天"级定时，工程上更常用 **RTC（第 10 章）**；级联主要用于**同步多个定时器**（如三相 PWM） |

## 练习 5 · 多任务调度器（极简版）

### 代码

```c
/* ---------- 1. 时基：定时器只负责累加 ---------- */
volatile uint32_t g_tick_ms = 0;

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        g_tick_ms++;
    }
}
```

```c
/* ---------- 2. 任务表 ---------- */
typedef void (*Task_Fn_t)(void);

typedef struct
{
    uint32_t   interval;        /* 周期 ms */
    uint32_t   last;            /* 上次执行时刻 */
    Task_Fn_t  fn;
} Sched_Task_t;

static void Task_Led1(void)  { Led_Toggle(LED_1); }     /* 500ms */
static void Task_Led2(void)  { Led_Toggle(LED_2); }     /* 1s    */
static void Task_Beat(void)  { /* 预留：串口打心跳，第 07 章 */ }

static Sched_Task_t g_tasks[] =
{
    {  500U, 0U, Task_Led1 },
    { 1000U, 0U, Task_Led2 },
    { 2000U, 0U, Task_Beat },
};

#define TASK_NUM   (sizeof(g_tasks) / sizeof(g_tasks[0]))

/* ---------- 3. 调度器：每圈扫一遍，谁的周期到了就执行 ---------- */
void Sched_Run(void)
{
    for (uint8_t i = 0U; i < TASK_NUM; i++)
    {
        /* ★ 减法比较：溢出安全（见 README 自我检测第 8 题） */
        if ((uint32_t)(g_tick_ms - g_tasks[i].last) >= g_tasks[i].interval)
        {
            g_tasks[i].last = g_tick_ms;
            g_tasks[i].fn();
        }
    }
}
```

```c
/* ---------- 4. 主循环 ---------- */
while (1)
{
    Sched_Run();                    /* 三个周期任务 */
    Key_Task(KEY1, LED_1);          /* 事件任务混进来也行 */
    Key_Task(KEY2, LED_2);
}
```

### 标准答案说明

| 项 | 说明 |
|---|---|
| **`last = g_tick_ms` vs `last += interval`** | 前者简单、**有微小漂移**（最多晚一圈主循环）；后者**无漂移但可能"追赶突发"**。教学用前者，高精度用后者 |
| **必须用减法比较** | `g_tick_ms == last + interval` 会因**漏检**永久停摆（README 第 8 题） |
| **加任务只改表格** | 和 `led.c` / `key.c` 的表格法同一种风格 |
| **这是协作式调度** | ⚠️ **任何一个 task 里调 `HAL_Delay()`，其他任务全部停摆** |
| 为什么叫"协作式" | 任务必须**自己主动让出**（尽快返回）。FreeRTOS 是"抢占式"——谁优先级高谁先跑，由内核强制切换 |

> **这个 40 行的调度器就是 FreeRTOS 的雏形。**
> 第 16~17 章你会看到它的完整形态：任务栈、优先级、抢占、信号量、队列。
> **现在先理解"1ms 时基 + 时间戳比较"这个骨架 —— 那就是所有 RTOS 的心跳。**

## 练习 6 · 寄存器重写 + 代码体积对比

### 已完成

任务 C 已经把 `Tim_Init()` / `Tim_IrqHandler()` 用寄存器重写过了（见 `Driver/tim.c` 的 `TIM_USE_REGISTER` 分支）。

### 体积累积对比方法

**方法 1 · EIDE 构建输出**
构建完成后，输出栏会打印 `Program Size: Code=xxxx RO-data=xxx ...`，直接对比两个版本的 `Code`。

**方法 2 · 看 `.map` 文件**
`build/` 目录下的 `.map` 文件，搜索 `HAL_TIM_Base_Init` / `HAL_TIM_IRQHandler`，看各占多少字节。

**方法 3 · 命令行**

```
arm-none-eabi-size build/xxx.elf
```

### 标准答案（结论）

| 对比项 | HAL 版 | 寄存器版 | 差异 |
|---|---|---|---|
| 代码体积 | 略大 | **小几百字节** | 差距**不大**（因为工程里其他模块还在用 HAL，`HAL_Init`/`HAL_GPIO` 等照样链接进去） |
| **ISR 执行速度** | 慢 | **快** ⭐ | `HAL_TIM_IRQHandler()` 要依次检查 CC1~CC4、Break、Trigger、Update…**一大堆无关标志**；寄存器版只查 `UIF` 一个位 |
| 可读性 | 好 | 差 | HAL 胜 |
| 可移植性（F1→F4） | 好 | 差 | HAL 胜 |

### ⭐ 真正值得记住的结论

```
寄存器版的价值不在"省空间"，而在：
    ① ISR 更快（少查一堆无关标志）
    ② 完全可控（不会被库的额外行为影响）

但代价是：
    ③ 可读性差、可移植性差、容易写错位

所以工程上的选择：
    初始化 → 用 HAL（一次性，不在乎那点开销）
    高频 ISR → 需要时手写寄存器（每秒上万次，差别就放大了）
```

> **这就是"两种都会"的意义**：不是二选一，而是**知道什么场景用哪个**。

## 附加 · 微秒级延时函数（最后一项学习目标）

### 推荐方案：占用一个空闲定时器（TIM4）

**优点**：不碰 SysTick，不影响 HAL 时基；精度高。

```c
/* Driver/delay.c */
#include "stm32f1xx_hal.h"

void Delay_Init(void)
{
    RCC->APB1ENR |= RCC_APB1ENR_TIM4EN;

    TIM4->PSC = 71U;                    /* 72MHz / 72 = 1MHz → 1 个计数 = 1us */
    TIM4->ARR = 0xFFFFU;                /* 最大 65535us ≈ 65ms */
    TIM4->EGR = TIM_EGR_UG;
    TIM4->SR  = 0;

    /* 注意：不开中断！只当计数器用 */
    TIM4->CR1 |= TIM_CR1_CEN;           /* 自由运行 */
}

void Delay_Us(uint16_t us)              /* 上限 65535us */
{
    /* CNT 是 16 位，会回绕。
     * 用 (uint16_t) 做强转 → 天然做 mod 65536 运算 → 回绕安全 */
    uint16_t start = (uint16_t)TIM4->CNT;

    while ((uint16_t)((uint16_t)TIM4->CNT - start) < us)
    {
        /* 忙等 */
    }
}
```

**关键点**：

| 项 | 说明 |
|---|---|
| 为什么 `PSC = 71` | 72MHz / (71+1) = **1MHz** → 1 个计数正好 1μs（好算） |
| 为什么 `(uint16_t)` 强转 | CNT 16 位会从 65535 回绕到 0。强转成 `uint16_t` 做减法 = **mod 2^16 运算**，回绕天然正确（和练习 5 的减法比较同一个道理） |
| 为什么不开中断 | 它是"秒表"，不需要通知任何人 |
| **最大延时** | 65535μs ≈ 65ms，超过要循环 |

### 备选方案：SysTick 轮询（不占外设，但有坑）

```c
/* ⚠️ 与 HAL 时基共用 SysTick，务必【不要】关掉 TICKINT，否则 HAL_Delay 全废 */
void Delay_Us_SysTick(uint16_t us)
{
    uint32_t load  = SysTick->LOAD;      /* ≈ 71999（1ms @72MHz） */
    uint32_t start = SysTick->VAL;
    uint32_t ticks = (uint32_t)us * 72U; /* 72MHz → 1us = 72 个计数 */

    if (ticks > load) return;            /* 一次最多测 1ms */

    while (1)
    {
        uint32_t cur = SysTick->VAL;
        uint32_t elapsed = (cur <= start) ? (start - cur) : (load - cur + start);
        if (elapsed >= ticks) break;
    }
}
```

**坑**：

| 坑 | 说明 |
|---|---|
| **一次最多 1ms** | `LOAD` 只有 71999，超过就回绕了 |
| **被中断打断会变长** | 忙等期间来了中断，延时就变长 |
| **和 HAL 时基共用** | 绝不能改 `SysTick->LOAD` 或关 `TICKINT` |

### ⚠️ 微秒延时的根本限制（重要）

```
忙等延时（无论哪种实现）都【会被中断打断】
        ↓
要求严格的时序（±1us）必须临时关中断
        ↓
        __disable_irq();
        Delay_Us(10);
        __enable_irq();
```

**什么时候真的需要它**：

| 场景 | 精度要求 | 章节 |
|---|---|---|
| **DHT22 单总线**（温湿度） | **μs 级，必须关中断** | **第 10 章** |
| WS2812 灯带 | ±150ns，很苛刻 | 拓展 |
| HC-SR04 超声波测距 | μs 级（但那是测脉冲宽度，用输入捕获更合适） | 第 09 章 |
| 按键消抖、LED 闪烁 | ms 级 → `HAL_Delay` 或定时器 | 已完成 |

> **先把这个函数放着 —— 第 10 章做 DHT22 时你会立刻用到它，而且会亲手体会"为什么必须关中断"。**

```
### HAL_Delay vs 定时器（周期任务漂移）
| 版本 | 1 分钟实测 | 结论 |
|---|---|---|
| HAL_Delay(1000) × 60 | ? ms | 有 +1tick 固有开销 |
| TIM2 1ms × 1000 × 60 | ? ms | 无累积漂移 |

### 破坏性实验：写错清标志
| 写法 | 现象 |
|---|---|
| TIM2->SR = (uint32_t)~TIM_SR_UIF | 正常，LED1 每 500ms 翻转 |
| TIM2->SR = TIM_SR_UIF（写 1） | LED1 半亮、按键失效、主循环饿死 |
| 整行删掉（不清） | 同上 |

原因：TIMx->SR 是 rc_w0（写 0 清），写 1 无效 → UIF 恒为 1 → ISR 无限重入。

### 软件 PWM
| 级数 | ISR 周期 | PWM 频率 | 视觉效果 |
|---|---|---|---|
| 100 级 | 1ms | 10Hz | 明显闪烁 |
| 100 级 | 0.1ms | 100Hz | 开始像"变暗" |
| 20 级 | 1ms | 50Hz | 有点闪，但亮度台阶粗 |
结论：频率 × 分辨率 = 1/ISR周期，两者此消彼长；CPU 占用 ∝ ISR 频率
      → 这正是第 05 章硬件 PWM 要解决的问题
```
